# Feature Specification: 지도 표시 고도화 — 구역 세분화 표시

**Feature Branch**: `002-airspace-zone-detail`

**Created**: 2026-09-23

**Status**: Draft

**Input**: User description: "이슈 #24: 지도 표시 고도화 — 14종 구역 세분화 표시. 국토부 드론 원스톱(docs/draft/drone_onestop_reference.md) 참고. #14는 VWorld typename 4개(lt_c_aisprhc/aisresc/aisctrc/aismoac/aisuac)를 불가/제한/가능 3색으로 단순화했다. 원스톱 문서는 14종 구역과 구역번호(R101~R156)까지 표시한다. #14가 이미 제외한 typename은 우선 추가 대상이고, 나머지 구역 종류는 VWorld WFS에 대응 레이어가 있는지 확인되지 않아 이 스펙 단계에서 조사부터 진행해야 한다."

## Clarifications

### Session 2026-09-23

- Q: 3그룹 체계의 의미를 무엇으로 확정할까? → A: **불가**(비행 자체가 불가능, 예: 군사지역·공항 인근) / **승인후비행가능**(사전 승인·신고를 받으면 비행 가능) / **승인불요**(별도 승인 없이 비행 가능 — 폴리곤 데이터가 없는 지역은 기본적으로 이 상태로 간주).
- Q: 위험구역(aisdngc, 사격장 등 군사/위험 시설)은 어느 그룹인가? → A: **불가** — 실제 위험이 상존해 승인 여부와 무관하게 비행이 사실상 불가능하다고 판단.
- Q: 드론시범사업구역(aisdronezone, 정부 지정 드론 친화구역)은 어느 그룹인가? → A: **승인불요** — 정부가 드론 비행을 장려하려고 지정한 구역으로, 구역 밖보다 규제가 적거나 간소화된 경우가 많다고 판단.
- Q: 국립자연공원(wgisnpgug)은 어느 그룹인가? → A: **승인후비행가능** — 자연공원법상 공원 내 드론 비행은 일반적으로 공원사무소/관리청 사전 허가가 필요하다고 판단.
- Q: 3색만으로는 같은 색 안에 여러 구역 종류(예: 불가 그룹 안에 비행금지/임시비행금지/위험구역 3종)가 섞여 구분이 안 되는데, 어떻게 구분할까? → A: 지도 위 색상은 3색을 유지하되, 각 폴리곤이 정확히 어떤 구역 종류인지는 **사용자가 확인할 수 있어야 한다**(클릭/탭 시 구역 종류 명칭 노출). 상세 안내 UI(주소/담당자 등 포함한 전체 정보 패널)는 #27에서 다루므로, 이 이슈에서는 최소한 "이 폴리곤이 정확히 무슨 구역인지" 식별 가능한 수준까지만 구현한다.

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 사용자가 더 많은 종류의 규제구역을 지도에서 확인할 수 있다 (Priority: P1)

사용자가 지도를 볼 때, 기존에 표시되지 않던 구역 종류(경계구역, 비행장교통구역, 경량항공기 이착륙장, 위험구역, 드론시범사업구역, 임시비행금지구역, 국립자연공원)도 함께 폴리곤으로 표시되어, 더 넓은 범위의 비행 제약 정보를 한 지도에서 확인할 수 있다.

**Why this priority**: 지도 표시가 이 서비스의 핵심 가치이며, 표시 구역이 늘어날수록 사용자가 실제 필요한 정보(내가 띄우려는 곳이 안전한가)에 더 가까워진다.

**Independent Test**: 새로 추가된 구역이 실제로 존재하는 지역(예: 국립공원 인근)으로 지도를 이동시켰을 때, 해당 폴리곤이 색상과 함께 렌더링되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 지도가 로드된 상태, **When** 사용자가 새로 추가된 구역이 존재하는 위치를 본다, **Then** 해당 구역이 세 그룹(불가/승인후비행가능/승인불요) 중 올바른 그룹의 색상으로 표시된다.
2. **Given** 여러 구역이 겹치는 위치, **When** 사용자가 그 위치를 본다, **Then** 기존과 동일하게 규제가 강한 구역(불가 > 승인후비행가능 > 승인불요)이 우선적으로 위에 그려진다.
3. **Given** 어떤 구역 폴리곤도 존재하지 않는 위치, **When** 사용자가 그 위치를 본다, **Then** 별도 폴리곤 없이 표시되며 이는 승인 없이 비행 가능한 지역으로 해석된다.

---

### User Story 2 - 사용자가 구역의 식별 번호를 확인할 수 있다 (Priority: P2)

사용자가 비행금지/제한구역을 볼 때, 국토부 원스톱 지도처럼 구역 식별 번호(예: R75, RK P73A)가 함께 표시되어 다른 문서(항공고시보 등)와 대조할 수 있다.

**Why this priority**: 식별 번호는 전문 사용자(항공고시보 대조, 관계기관 문의)에게 유용하지만, 구역 자체가 보이는 것(User Story 1)보다는 부가 정보라 우선순위가 낮다.

**Independent Test**: 식별 번호가 있는 구역(비행금지/제한구역)을 클릭하거나 확대했을 때 번호 라벨이 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 비행금지구역이 표시된 상태, **When** 사용자가 해당 구역을 본다, **Then** 구역 식별 번호(예: RK P73A)가 라벨로 표시된다.
2. **Given** 비행제한구역이 표시된 상태, **When** 사용자가 해당 구역을 본다, **Then** 구역 식별 번호(예: R75)가 라벨로 표시된다.

---

### User Story 3 - 사용자가 같은 색상 안에서도 정확한 구역 종류를 구분할 수 있다 (Priority: P1)

3색 그룹(불가/승인후비행가능/승인불요) 안에는 여러 구역 종류가 섞여 있다(예: 불가 그룹에 비행금지/임시비행금지/위험구역 3종). 사용자가 폴리곤을 클릭(또는 탭)하면 그 폴리곤이 정확히 어떤 구역 종류인지(예: "위험구역", "임시비행금지구역") 확인할 수 있다.

**Why this priority**: 색상만으로는 "왜 안 되는지"를 알 수 없어 사용자가 다음 행동(문의처를 찾거나 우회 경로를 정하는 등)을 판단하기 어렵다. 구역이 늘어날수록(User Story 1) 한 색 안에 섞이는 종류도 늘어나므로, 종류 자체를 늘리는 작업과 동시에 갖춰야 실질적 가치가 있다.

**Independent Test**: 같은 색 그룹에 속한 서로 다른 두 구역(예: 불가 그룹의 비행금지구역과 위험구역)을 각각 클릭해, 서로 다른 구역 종류 명칭이 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 지도 위에 여러 종류의 폴리곤이 표시된 상태, **When** 사용자가 특정 폴리곤을 클릭한다, **Then** 해당 폴리곤의 정확한 구역 종류 명칭(예: "위험구역")이 표시된다.
2. **Given** 같은 색상 그룹에 속한 서로 다른 두 구역, **When** 사용자가 각각을 클릭한다, **Then** 서로 다른 구역 종류 명칭이 표시된다.

---

### Edge Cases

- 식별 번호 데이터가 없는 구역 종류(경계구역, 위험구역 등 원본 데이터에 코드 필드가 없는 경우)는 번호 라벨 없이 폴리곤만 표시한다.
- 동일 위치에 여러 구역이 겹칠 때, 라벨도 여러 개 겹칠 수 있다 — 이번 범위에서는 겹침 방지 로직(라벨 자동 배치 등)을 다루지 않는다.
- 특정 구역 종류의 API 응답이 비어 있거나 실패해도(#14의 기존 정책과 동일하게) 해당 그룹만 렌더링을 생략하고 나머지는 정상 표시한다.
- 장애물공역, 사전협의구역, 문화재보호구역은 이번 범위에서 제외한다(아래 Assumptions 참고).

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 시스템은 기존 3그룹(불가/승인후비행가능/승인불요) 체계를 유지한 채, 다음 신규 구역 종류를 추가로 표시해야 한다: 경계구역, 비행장교통구역, 경량항공기 이착륙장, 위험구역, 드론시범사업구역, 임시비행금지구역, 국립자연공원(국립).
- **FR-002**: 시스템은 각 구역을 다음 그룹으로 분류해 표시해야 한다:
  | 그룹                                                                                                                         | 구역 종류 (typename)                                                                                                                                                                                                                                     |
  | ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | 불가                                                                                                                         | 비행금지구역(`lt_c_aisprhc`, 기존), 임시비행금지구역(`lt_c_aistemp`, 신규), 위험구역(`lt_c_aisdngc`, 신규)                                                                                                                                               |
  | 승인후비행가능                                                                                                               | 비행제한구역(`lt_c_aisresc`, 기존), 관제권(`lt_c_aisctrc`, 기존), 군작전구역(`lt_c_aismoac`, 기존), 경계구역(`lt_c_aisaltc`, 신규), 비행장교통구역(`lt_c_aisatzc`, 신규), 경량항공기이착륙장(`lt_c_aisfldc`, 신규), 국립자연공원(`lt_c_wgisnpgug`, 신규) |
  | 승인불요                                                                                                                     | 초경량비행장치공역 UA(`lt_c_aisuac`, 기존), 드론시범사업구역(`lt_c_aisdronezone`, 신규)                                                                                                                                                                  |
  | 폴리곤 데이터가 존재하지 않는 지역은 위 표에 없는 기본 상태로, 승인불요 그룹과 동일하게 해석한다(별도 폴리곤을 그리지 않음). |
- **FR-003**: 시스템은 비행금지구역과 비행제한구역에 대해 구역 식별 번호를 지도 라벨로 표시해야 한다.
- **FR-004**: 시스템은 식별 번호 데이터가 없는 구역 종류에 대해서는 라벨 없이 폴리곤만 표시해야 한다.
- **FR-005**: 시스템은 특정 구역 그룹의 데이터 조회가 실패해도 나머지 그룹은 정상적으로 표시해야 한다(기존 #14 정책 유지).
- **FR-006**: 시스템은 장애물공역, 사전협의구역, 문화재보호구역을 이번 범위에서 표시하지 않아야 한다(공개 데이터 소스 미확보).
- **FR-007**: 시스템은 사용자가 폴리곤을 클릭(또는 탭)했을 때 그 폴리곤의 정확한 구역 종류 명칭(예: "위험구역", "비행금지구역")을 확인할 수 있게 해야 한다 — 같은 색상 그룹 안의 여러 구역 종류를 구분하기 위함이다. 주소/담당자 등을 포함한 전체 안내 패널은 #27(클릭 시 비행승인 안내) 범위이며, 이 이슈에서는 구역 종류 명칭 노출까지만 다룬다.

### Key Entities

- **구역(Zone)**: 지도에 폴리곤으로 표시되는 항공 규제 구역. 속성: 구역 종류, 규제 그룹(불가/승인후비행가능/승인불요), 식별 번호(있는 경우), 지오메트리(폴리곤).

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 사용자는 기존 5종(비행금지/제한/관제권/군작전/UA)에 더해 최소 7종의 신규 구역 종류를 지도에서 확인할 수 있다.
- **SC-002**: 비행금지·비행제한구역을 보는 사용자의 100%가 해당 구역의 식별 번호를 함께 확인할 수 있다(데이터가 존재하는 경우).
- **SC-003**: 구역 그룹 중 하나의 데이터 조회가 실패해도 나머지 구역 표시에는 영향이 없다(장애 격리 유지).
- **SC-004**: 사용자는 지도 위 어떤 구역 폴리곤을 클릭하더라도 그 구역의 정확한 종류 명칭을 확인할 수 있다(100%).

## Assumptions

- **데이터 소스**: 신규 구역 7종은 모두 VWorld WFS에 이미 공개된 typename(`docs/API_REFERENCE.md` 실증 완료)을 사용하며, 별도 API 키 신청이나 인증 절차가 추가로 필요하지 않다.
- **범위 제외**: 장애물공역, 사전협의구역은 VWorld·data.go.kr 어디에도 공개 API가 없음이 확인되어(`docs/API_REFERENCE.md` "미확인 사항") 이번 범위에서 제외한다. 문화재보호구역은 후보 API가 있으나 활용신청 후에야 실제 파라미터가 제공되어(자동승인이라도 신청·확인 절차가 필요) 별도 후속 작업으로 미룬다.
- **국립자연공원 범위**: 도립(`lt_c_wgisnpdo`)/군립(`lt_c_wgisnpgun`)은 제외하고 국립(`lt_c_wgisnpgug`)만 포함한다 — 원스톱 문서의 "국립자연공원" 표기와 가장 직접적으로 대응하며, 도립/군립까지 포함할지는 계획 단계 또는 후속 이슈에서 필요 시 확장한다.
- **구역번호 데이터**: 비행금지(`prh_lbl_1`)/비행제한(`res_lbl_1`) typename의 응답에 이미 식별 번호 필드가 포함되어 있음을 확인했다(`docs/API_REFERENCE.md` "실제 응답 스키마"). 다른 신규 구역 종류는 유사 필드 존재 여부를 계획 단계에서 확인한다.
