# Quickstart: 지도 표시 고도화 검증

## 사전 준비

```bash
pnpm test   # tagFeatureZoneType 단위 테스트 통과 확인
pnpm dev
```

## 검증 절차

### 1. 신규 구역이 표시되는지 확인 (User Story 1, SC-001)

1. 지도에서 국립공원(예: 월출산), 위험구역(사격장 인근), 드론시범사업구역(예: 고흥) 등 신규 typename이 존재하는 지역으로 이동한다.
2. 해당 위치에 폴리곤이 렌더링되고, 색상이 spec FR-002 매핑대로인지 확인한다(불가=빨강, 승인후비행가능=회색, 승인불요=녹색 — 기존 색상 유지).

### 2. 클릭 시 정확한 구역 종류가 보이는지 확인 (User Story 3, FR-007, SC-004)

1. "불가" 색상(빨강)으로 표시된 서로 다른 폴리곤 두 개를 각각 클릭한다 — 예: 비행금지구역 1개, 위험구역 1개.
2. 각각 클릭했을 때 "비행금지구역", "위험구역"처럼 서로 다른 구역 종류 라벨이 표시되는지 확인한다.
3. "승인후비행가능" 그룹 안의 서로 다른 구역(예: 관제권 vs 경계구역)도 동일하게 확인한다.

### 3. 구역 번호 라벨 확인 (User Story 2, SC-002)

1. 비행금지구역, 비행제한구역이 있는 위치로 이동한다.
2. 각 폴리곤에 구역 식별 번호(예: `RK P73A`, `R75`)가 라벨로 표시되는지 확인한다.

### 4. 장애 격리 확인 (Edge Case, SC-003)

1. 브라우저 개발자도구 네트워크 탭에서 특정 typename 요청을 실패로 시뮬레이션하거나, 기존 #14 검증 방식(네트워크 차단)을 재사용한다.
2. 해당 그룹만 렌더링이 생략되고 나머지 그룹은 정상 표시되는지, 에러 토스트가 뜨는지 확인한다.

### 5. 자동화 테스트

```bash
pnpm test
```

`tagFeatureZoneType` 단위 테스트를 포함해 기존 스위트가 모두 통과하는지 확인한다.

## 예상 결과

- 기존 5종(비행금지/제한/관제권/군작전/UA)에 더해 신규 7종이 지도에 표시된다.
- 같은 색상 안에서도 클릭하면 정확한 구역 종류를 구분할 수 있다.
- 비행금지/제한구역에는 구역 번호가 라벨로 보인다.
- 특정 그룹 조회 실패가 다른 그룹에 영향을 주지 않는다.
