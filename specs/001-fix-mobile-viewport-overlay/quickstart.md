# Quickstart: 모바일 뷰포트 하단 플로팅 요소 노출 수정 검증

## 사전 준비

```bash
pnpm dev
```

## 검증 절차

### 1. 데스크톱 회귀 없음 확인 (SC-002)

1. 일반 데스크톱 브라우저 창(주소창 표시 상태)에서 `http://localhost:<port>`(또는 rsbuild가 출력한 URL) 접속.
2. 지도가 브라우저 창 전체를 채우는지, 우하단 범례가 기존과 동일한 위치에 보이는지 확인.

### 2. 모바일 에뮬레이션으로 1차 확인

1. 브라우저 개발자도구 → 기기 툴바(반응형/모바일 에뮬레이션) 활성화, iPhone 계열 프리셋 선택.
2. 페이지 새로고침 후, 우하단 `AirspaceLegend`와 좌하단 Kakao 축척 표시가 뷰포트 안에 온전히 보이는지 확인.
3. 에뮬레이터의 "주소창 표시/숨김" 토글(가능한 도구의 경우)이나 세로/가로 회전을 눌러 뷰포트 크기가 바뀔 때도 두 요소가 계속 화면 안에 있는지 확인.

### 3. 실기기 확인 (SC-001, 가장 신뢰도 높은 검증)

1. 같은 네트워크의 모바일 기기(iOS Safari, Android Chrome)에서 개발 서버 URL로 접속(`pnpm dev`가 노출하는 LAN 주소 사용, 필요 시 `--host` 옵션).
2. 페이지 로드 직후(주소창이 펼쳐진 상태)와, 아래로 스크롤해 주소창이 축소된 상태 양쪽에서 범례/축척이 화면 안에 보이는지 확인.
3. 기기를 가로로 회전해도 동일하게 확인.

### 4. 자동화 테스트

```bash
pnpm test
```

기존 스위트가 모두 통과하는지 확인한다(이 변경은 CSS 클래스 수준이라 신규 테스트를 추가하지 않음 — plan.md Technical Context의 테스트 전략 참고).

## 예상 결과

- 데스크톱: 기존과 동일하게 지도가 뷰포트 전체를 채움.
- 모바일(에뮬레이션/실기기, 주소창 상태 무관): 우하단 범례와 좌하단 축척이 항상 화면 안에서 보임.
