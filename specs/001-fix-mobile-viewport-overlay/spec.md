## User Scenarios & Testing _(mandatory)_

### User Story 1 - 모바일에서 범례를 항상 확인할 수 있다 (Priority: P1)

모바일 브라우저(iOS Safari, Android Chrome 등)로 지도 페이지를 열었을 때, 비행 구역 범례(우하단 플로팅 패널)가 주소창/도구모음 유무와 관계없이 항상 화면 안에서 보인다.

**Why this priority**: 범례가 안 보이면 사용자가 지도 위 색상이 무엇을 뜻하는지 알 수 없어 서비스의 핵심 가치(구역 판별)가 무너진다. 모바일 트래픽 비중이 큰 서비스 특성상 가장 시급하다.

**Independent Test**: 모바일 기기(또는 브라우저 개발자도구의 모바일 에뮬레이션, 주소창이 자동 축소/확장되는 실제 iOS Safari 포함)로 지도 페이지에 접속해, 페이지 로드 직후와 스크롤/주소창 축소 이후 모두 범례 패널 전체가 뷰포트 안에서 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** iOS Safari로 지도 페이지를 처음 연 상태(주소창이 펼쳐진 상태), **When** 페이지가 로드되면, **Then** 우하단 범례 패널 전체가 화면 안에 보인다.
2. **Given** iOS Safari에서 주소창이 축소되어 뷰포트가 커진 상태, **When** 사용자가 화면을 본다, **Then** 범례 패널은 여전히 화면 하단 안쪽에 위치하며 잘리거나 화면 밖으로 밀려나지 않는다.
3. **Given** Android Chrome 등 다른 모바일 브라우저, **When** 지도 페이지를 연다, **Then** 동일하게 범례 패널이 화면 안에 보인다.

---

### User Story 2 - 모바일에서 지도 축척을 항상 확인할 수 있다 (Priority: P2)

모바일 브라우저로 지도 페이지를 열었을 때, Kakao 지도 기본 축척 표시(좌하단)가 항상 화면 안에서 보인다.

**Why this priority**: 축척은 지도 조작 시 위치 감각을 돕는 보조 정보로, 범례보다 핵심도는 낮지만 동일한 근본 원인(뷰포트 계산)으로 발생하는 문제라 같은 수정으로 함께 해결된다.

**Independent Test**: User Story 1과 동일한 환경에서 좌하단 축척 표시가 항상 화면 안에 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** iOS Safari로 지도 페이지를 연 상태(주소창 펼침/축소 어느 쪽이든), **When** 사용자가 지도를 확대/축소한다, **Then** 좌하단 축척 표시가 항상 화면 안에 보인다.

---

### Edge Cases

- 매우 작은 화면(구형 소형 기기, 가로 320px급)에서도 범례 패널이 다른 UI 요소(로딩 스피너 등)와 겹치지 않고 화면 안에 보여야 한다.
- 기기 회전(세로↔가로) 시에도 두 요소 모두 화면 밖으로 밀려나지 않아야 한다.
- 데스크톱 브라우저에서는 기존 동작(전체 화면을 채우는 지도)이 그대로 유지되어야 한다 — 이번 수정으로 인한 회귀가 없어야 한다.
- 모바일 브라우저 중 동적 뷰포트 단위(`100dvh` 등) 미지원 구형 브라우저에서도 최소한 기존 수준(100vh) 이하로 깨지지 않아야 한다(점진적 개선/폴백).

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 지도 페이지 컨테이너는 모바일 브라우저의 주소창/도구모음 표시 여부와 무관하게, 실제로 사용자에게 보이는 뷰포트 영역을 벗어나지 않아야 한다.
- **FR-002**: 우하단 범례 패널은 뷰포트 하단 경계 안쪽에 항상 위치해야 하며, 브라우저 UI(주소창, 하단 탭바 등)에 가려지거나 화면 밖으로 잘려서는 안 된다.
- **FR-003**: 좌하단 지도 축척 표시는 뷰포트 하단 경계 안쪽에 항상 위치해야 하며, 화면 밖으로 잘려서는 안 된다.
- **FR-004**: 데스크톱 환경에서는 기존 레이아웃(지도가 뷰포트 전체를 채우는 동작)이 이번 수정 이후에도 동일하게 유지되어야 한다.
- **FR-005**: 수정 사항은 별도 기기/브라우저 감지(User-Agent 분기) 없이, CSS 수준의 뷰포트 단위 전환만으로 해결한다.

### Key Entities

이 기능은 UI 레이아웃 수정으로, 별도의 데이터 엔티티를 다루지 않는다.

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: iOS Safari, Android Chrome 등 주요 모바일 브라우저에서 지도 페이지 접속 시 범례 패널과 축척 표시가 100% 화면 안에서 보인다(주소창 표시/축소 상태 모두).
- **SC-002**: 데스크톱 브라우저에서 기존 레이아웃 대비 시각적 회귀가 없다(지도가 뷰포트 전체를 채우는 동작 유지).
- **SC-003**: 수정 후에도 기존 자동화 테스트(`pnpm test`)가 모두 통과한다.

## Assumptions

- "모바일 브라우저"는 iOS Safari, Android Chrome 최신 버전을 우선 대상으로 하며, 그 외 브라우저는 동일 CSS 기법(동적 뷰포트 단위)의 일반적 지원 범위를 따른다.
- 이번 수정은 CSS/레이아웃 단위의 문제로 간주하며, Kakao Maps SDK 자체의 축척 렌더링 로직은 변경하지 않는다(컨테이너 크기만 올바르게 잡아주면 SDK가 자체적으로 축척을 컨테이너 안에 그린다고 가정).
- E2E 테스트(Playwright 등 실기기/에뮬레이터 기반 시각 검증)는 CLAUDE.md 방침에 따라 이번 스펙에서 도입하지 않으며, 브라우저 개발자도구의 반응형/모바일 에뮬레이션 및 수동 확인으로 검증한다.
