# 스펙: WMS 모드 구역 클릭 안내

## 배경/목적

WMS 모드(#73)는 약 50MB 폴리곤 조회를 중단해서 클릭할 대상(폴리곤)이 없다. 지도를 클릭한 지점의 구역 종류를 폴리곤 모드와 같은 안내 박스(`AirspaceZoneOverlay`)로 보여 준다. 방식은 사용자 결정으로 **클릭 지점만 WFS 조회**로 정했다(전체를 받지 않아 #73 취지 유지, 기존 WFS/relay 재사용).

## 입력

- 사용자 이벤트: WMS 모드에서의 지도 클릭 (`kakao.maps.event.MouseEvent.latLng`)
- 켜진 typename 목록(범례 필터 반영, `TYPENAME_ZONE_LABELS` 순서 = 위험도 우선순위)

## 기대 동작

- [ ] 클릭 지점 ±0.0001°(약 10m) BBOX로 켜진 typename별 WFS `GetFeature`를 병렬 요청한다. BBOX는 `minLng,minLat,maxLng,maxLat`(기존 `KOREA_BBOX`와 같은 순서).
- [ ] BBOX는 근처 구역도 반환하므로, 응답 지오메트리로 **클릭 지점이 실제로 포함되는지**(`isPointInMultiPolygon`) 판정한다. 홀(국립공원 내부 ring) 안은 제외한다.
- [ ] 여러 구역에 걸치면 typename 순서상 먼저인(위험도 높은) 구역 하나만 안내한다(폴리곤 모드의 최상단 폴리곤과 같은 규칙).
- [ ] 해당하는 구역이 있으면 기존 `AirspaceZoneOverlay`를 클릭 좌표에 띄운다(`selectZone`).
- [ ] 구역이 없으면 열려 있던 안내를 닫는다(`clearZone`).
- [ ] WMS 모드가 아닐 때(폴리곤 모드)는 지도 클릭을 처리하지 않는다. 폴리곤 클릭 동작은 바뀌지 않는다.
- [ ] 모드를 바꾸면 열려 있던 안내를 닫는다.

## 엣지케이스

- [ ] 켜진 typename이 없으면 요청하지 않고 안내를 닫는다.
- [ ] 일부 typename 요청이 실패해도 다른 요청에서 포함 구역이 찾아지면 그것을 안내한다.
- [ ] 포함 구역이 없고 하나라도 실패했으면 "없음"이 아니라 오류로 취급해 토스트로 알린다(조회 실패를 빈 땅으로 오해하지 않게).
- [ ] 연속 클릭 시 늦게 도착한 이전 클릭의 응답은 무시한다(마지막 클릭만 반영).
- [ ] 범례에서 해당 종류를 끄면 열려 있던 안내가 닫힌다(기존 `useSelectedZone` 동작 유지).

## 범위 밖

- WMS `GetFeatureInfo` 방식(지원·CORS 불확실해 제외)
- 겹친 구역을 모두 나열하는 안내, 구역 이름·상세 속성 표시
- 프로덕션 응답 검증(배포 환경, #74)

## 관련 이슈

#75, #28

## 추가 (체감 지연 개선, 약 0.5초)

- [ ] 요청은 전부 동시에 시작하되 결과는 우선순위 순서로 확인한다. 높은 우선순위 구역이 확정되면 낮은 우선순위의 느린 응답을 기다리지 않는다. 낮은 우선순위가 먼저 도착해도 높은 우선순위 응답이 끝나기 전에는 확정하지 않는다.
- [ ] 확정되거나 오류로 끝나면 진행 중인 나머지 요청을 취소()한다. 새 클릭이 오면 이전 클릭의 요청도 취소한다.
- [ ] 클릭 즉시 그 좌표에 조회 중 표시()를 올리고, 마지막 클릭의 조회가 끝나면(적중·미적중·오류) 지운다. 요청이 필요 없는 경우(비활성, 켜진 typename 없음)에는 표시하지 않는다.
- [ ] 취소된 요청은 오류 토스트나 콘솔 오류를 남기지 않는다.
- 범위 밖: relay (서버 재배포 필요), 응답 크기 자체 축소, 묶음 요청(VWorld 지원 미확인)
