# 스펙: 공역 캐시 런타임 온오프

## 배경/목적

새로고침 버튼이 신선한 캐시에서 "최신 상태입니다."만 보여 갱신이 안 되는 것처럼 보이던 문제(#68)로, 캐시를 코드 상수(`AIRSPACE_CACHE_ENABLED=false`)로 꺼 두었다. 캐시를 다시 켜 검증하려면 코드 수정과 재배포가 필요해서, 사용자가 앱에서 직접 켜고 끌 수 있게 한다.

## 입력

- 사용자 이벤트: 지도 우측 컨트롤의 "공역 캐시" 버튼 → Popover의 Switch 토글
- 저장값: localStorage(`airspace-cache-setting`), zustand `persist`로 저장/복원

## 기대 동작

- [ ] 초기값(저장값 없음)은 꺼짐이다.
- [ ] Switch를 켜면 `enabled=true`가 되고 localStorage에 저장된다. 새로고침 후에도 유지된다.
- [ ] 꺼짐: 시작 시 하이드레이션 안 함, IndexedDB 저장 안 함, staleTime=Infinity, 포커스/주기 재조회 없음, 새로고침 버튼은 전 그룹 재조회.
- [ ] 켜짐: 시작 시 하이드레이션, 조회 성공 시 IndexedDB 저장, staleTime(24h, `VITE_AIRSPACE_STALE_TIME_MS`로 덮어쓰기 가능), 포커스/주기 재조회, 새로고침 버튼은 만료 그룹만 재조회하고 모두 최신이면 "최신 상태입니다. (마지막 갱신: HH:mm)".
- [ ] 런타임 전환은 즉시 쿼리 옵션에 반영된다(재시작 불필요). 하이드레이션만 앱 시작 시점의 저장값을 따른다.

## 엣지케이스

- [ ] localStorage를 쓸 수 없으면(시크릿 모드 등) 메모리에서만 동작하고 에러를 내지 않는다.
- [ ] 저장값이 손상되었으면 기본값(꺼짐)으로 시작한다.
- [ ] 끄더라도 IndexedDB의 기존 데이터는 지우지 않는다(다시 켤 때 재사용).
- [ ] 런타임에 켠 직후에는 메모리의 데이터가 IndexedDB에 아직 없다. 다음 조회 성공 때부터 저장된다(현재 데이터를 즉시 저장하지 않음).

## 범위 밖

- 캐시 삭제 버튼, 캐시 용량/시각 표시
- 그룹 부분 실패 시 미저장 문제(`Promise.all` → `allSettled`)
- `refetchInterval`의 브라우저 검증
