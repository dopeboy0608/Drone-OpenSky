# 스펙: 지도 UX 개선 (줌레벨/현재위치/재조회 버튼 + 공역 정보 오버레이)

## 배경/목적

지도 초기 진입 시 줌레벨이 상황에 안 맞고, 현재 위치를 지도에서 확인할 방법이 없으며, 공역
데이터/현재위치를 다시 조회할 UI가 없다. 공역 정보 오버레이도 모바일에서 읽기 어려울 만큼
작다. grill-me 인터뷰(이슈 #34)로 확정된 요구사항을 정리한다.

## 입력

- **기본 줌레벨**: 카카오 지도 SDK `level` prop. 축척 컨트롤 기준 1km에 해당하는 값(사전 조사:
  level 1~5가 각각 20/30/50/100/250m — Kakao DevTalk 확인, [https://devtalk.kakao.com/t/km/115378](https://devtalk.kakao.com/t/km/115378));
  이후 250 → 500 → 1000m로 이어진다고 보고 **level 7**을 기본값으로 채택. 공식 문서에 표가
  없어 실측 확정값은 아니며, 필요 시 조정 가능하도록 상수로 분리한다.
- **현재위치**: `navigator.geolocation.getCurrentPosition` 결과(성공 시 좌표, 실패 시 없음).
- **재조회 버튼 클릭**: 사용자 이벤트(클릭).
- **이동 버튼 클릭**: 사용자 이벤트(클릭), 마지막으로 알고 있는 현재위치 좌표.
- **폴리곤 재조회 버튼 클릭**: 사용자 이벤트(클릭).

## 기대 동작

- [ ] 지도 최초 로드 시 `level`이 1km 스케일에 해당하는 값(잠정 7)으로 표시된다. 축척
      컨트롤 UI 자체는 노출하지 않는다.
- [ ] 위치 권한이 허용되면 현재위치에 카카오 기본 마커가 표시된다.
- [ ] 위치 권한이 거부/실패하면 마커를 표시하지 않고, 기존처럼 지도는 서울 기본 좌표로
      폴백한다.
- [ ] "폴리곤 재조회" 버튼 클릭 시 전국(`KOREA_BBOX`) 대상 공역 데이터를 다시 조회한다
      (bounds 기반 재조회 아님).
- [ ] "현재위치 재조회" 버튼 클릭 시 GPS 위치를 다시 요청해 마커 위치만 갱신한다. 지도
      중심은 이동하지 않는다.
- [ ] "현재위치 재조회" 실패(권한 거부 등) 시 토스트로 실패를 안내한다.
- [ ] "현재위치로 이동" 버튼 클릭 시 마지막으로 알고 있는 현재위치로 지도 중심만 이동
      (pan)한다. 줌레벨은 변경하지 않는다.
- [ ] 공역 정보 오버레이(`AirspaceZoneOverlay`)에 닫기 버튼이 추가된다.
- [ ] 공역 정보 오버레이가 모바일 뷰포트에서도 읽기 쉬운 크기(현재 `text-xs px-2 py-1`보다
      확대)로 렌더링된다.
- [ ] 신규 버튼들은 기존 `AirspaceLegend`와 동일한 스타일(흰 배경/rounded-md/shadow)을
      따르는 플로팅 UI로 배치된다.

## 엣지케이스

- [ ] `navigator.geolocation`이 아예 없는 환경(구형 브라우저 등): 마커 미표시, 재조회 버튼
      클릭 시 토스트 안내.
- [ ] 최초 로드 시 위치 권한이 아직 허용되지 않은 상태에서 "현재위치로 이동" 버튼을 누르는
      경우: 알고 있는 현재위치가 없으므로 아무 동작도 하지 않는다(비활성화 또는 토스트 안내).
- [ ] 폴리곤 재조회 중 다시 버튼을 연타하는 경우: TanStack Query의 기존 로딩 상태 표시를
      그대로 활용하고 별도 debounce는 두지 않는다(기존 로딩 스피너로 충분).
- [ ] 공역 정보 오버레이가 열린 상태에서 다른 폴리곤을 클릭하는 경우: 기존 동작(선택된 zone
      교체) 유지, 새로 추가하는 닫기 버튼과 무관.

## 범위 밖

- bounds(뷰포트) 기준 공역 재조회 (전국 고정 조회 유지)
- 위치 추적(watchPosition) 등 실시간 위치 업데이트
- 커스텀 마커 아이콘 디자인
- 축척 컨트롤 UI 상시 노출
